# Disaster Recovery Car Rides Demo — Agent Instructions

## Overview
This directory (`e2e-demos/dr-car-rides`) implements an end-to-end Disaster Recovery (DR) demonstration and study using a real-time car-rides streaming pipeline.

The demonstration illustrates multi-region disaster recovery for streaming data architectures, including:
1. Active/Passive Kafka replication via Cluster Linking.
2. Schema replication via Schema Linking in `IMPORT` mode to preserve Schema IDs.
3. Stateful and stateless Flink SQL pipelines deployed across primary and DR regions.
4. Data lakehouse materialization with Confluent Tableflow (Iceberg).
5. Controlled failover (soft failover), ungraceful failover (promote failover), and failback procedures.
6. Sequence-based RPO and processing gap loss assessment (`assess_loss.py`).

## Component Responsibilities

### `IaC/` (Terraform layers)
Apply in order; each layer has its own state and `terraform.tfvars` (copy from `terraform.tfvars.example`). Layers 2 and 3 take plain variables generated by `scripts/tfvars-from-outputs.sh` (`terraform.tfvars.json`, gitignored).

| Layer | Runs from | Content |
|-------|-----------|---------|
| `00-primary-flink` | laptop | `flink.tf` (pool, SA, role bindings, API key), `producer.tf` (producer SA, Kafka/SR keys, `rides_raw` topic), `schemas.tf` (`rides_raw` key/value schemas registered by Terraform) |
| `01-dr-site` | laptop | `confluent.tf` (DR environment, Kafka cluster, Flink pool), `network.tf` (VPC, PrivateLink attachment, Route53), `bastion.tf` (SSM-only bastion), `service-accounts.tf` |
| `02-cluster-link` | DR bastion | `cluster-link.tf`: destination-initiated link primary -> DR, mirror topics |
| `03-schema-linking` | laptop | `schema-linking.tf`: DR SR `IMPORT` mode and schema exporter |

- `rides_raw` and its schemas are owned by Terraform; dbt only reads it via `source()`. `rides_clean` and `driver_stats` are created by the dbt deploy on each site and are not mirrored to DR (Layer 2 mirrors `rides_raw` only; Layer 3 exports only its two subjects).
- Never commit `terraform.tfstate*`, `terraform.tfvars*` or `.terraform/`.

### `pipelines/` (dbt-confluent Flink SQL)
- Replaces the former `flink-sql/` DDL/DML files and `deploy_manifest.json`.
- Run from `pipelines/` with `make <target> SITE=primary|dr` (`debug`, `compile`, `deploy`, `deploy-full`, `undeploy`, `drop-tables`, `teardown`). The Makefile sources `../scripts/export-env.sh <site>` so only one site is exported per invocation.
- Requires `scripts/iac-outputs.json` and the dbt profile `j9r` in `~/.dbt/profiles.yml`.
- `dbt run` does not recreate existing relations and cannot stop statements: after changing a query use `deploy-full` or `undeploy` + `drop-tables`; stopping statements uses `code/flink-sql/tools` with `teardown/deploy_manifest.json`.

### `scripts/`
- `export-env.sh <primary|dr>`: Exports cluster connection, REST endpoints, Schema Registry credentials, and Flink metadata (reads `iac-outputs.json`).
- `generate-outputs.sh`: Merges `terraform output -json` of every applied layer into `iac-outputs.json` (gitignored, contains secrets).
- `tfvars-from-outputs.sh <02-cluster-link|03-schema-linking>`: Writes `IaC/<layer>/terraform.tfvars.json` from `iac-outputs.json`.
- `push-outputs.sh` / `pull-outputs.sh`: Move `iac-outputs.json` laptop -> bastion through an SSM SecureString parameter (no secrets in SSM command history).
- `bastion-setup.sh` / `bastion-sync.sh`: Install tools on the bastion; copy non-secret code (Layer 2, scripts, python) to `/opt/dr-car-rides` via SSM.
- `peek-topic.sh primary|dr <topic>`: Wraps `python/peek_topic.py`; DR is read from the bastion because the Confluent Cloud message viewer cannot reach the private DR cluster.
- `failover-soft.sh`: Graceful failover (stop primary Flink DML, set DR SR to `READWRITE`, deploy DR Flink, retarget producer).
- `failover-promote.sh`: Ungraceful/mirror-promote failover.
- `failback.sh`: Step-by-step failback and reverse schema sync.
- `unset_env_var.sh`: Must be sourced; clears `KAFKA_*`/`FLINK_*`/`SCHEMA_REGISTRY_*` variables that the Confluent Terraform provider would otherwise read as a partial credential set.

### `python/` (Platform-Agnostic Tools)
- Managed with `uv`.
- Must remain platform-agnostic so the same tools work against Confluent Cloud, Confluent Platform, or Apache Kafka.
- Producer does not auto-register schemas in Schema Registry by default; it uses `use.latest.version` aligned with the schemas registered by `IaC/00-primary-flink/schemas.tf`.
- Supports sequence numbers (`seq`) in every event payload for loss measurement.
- `peek_topic.py` is read-only (no committed offsets), safe on mirror topics.

## Key DR Principles & Conventions

1. **Schema ID Preservation**: DR Schema Registry is initialized in `IMPORT` mode and kept synced with primary Schema Registry using Schema Exporters. This ensures schema IDs match between primary and DR clusters.
2. **Cluster Linking**: Mirror topics in DR receive mirrored events from primary source topics (`rides_raw`).
3. **Flink Deployment**:
   - In active/passive: Primary Flink runs DML. On failover, DR Flink statements are deployed with `earliest-offset` startup.
   - Statement names follow the dbt/manifest convention: `dr-dims-rides-clean`, `dr-facts-driver-stats`.
4. **Environment Isolation**: Never mix primary and DR environment variables in the same shell session. Always use `source scripts/export-env.sh <site>`.
